# Changelog

All notable changes to this project are documented in this file.

## [0.3.0rc1] - 2026-09-18

Major architecture release: the **Domain Pack SDK**, turning Groundspec from a small collection of built-in domain rules into an extensible, secure Domain Pack platform, plus two new official packs (`product-management`, `data-science-ml`). Existing behavior, contracts, and rule packs are fully preserved.

### Added

- **Domain Pack SDK** (`groundspec.packs.sdk`): a versioned manifest schema (`domain_pack.v0_1_0.schema.json`, validated via `groundspec.contract.validator.validate_domain_pack_dict`), deterministic discovery across official/project/user origins (`discovery.py`), a resolver computing dependency closure, version-range and conflict checking, and effective precedence (`resolver.py`), a canonical-JSON, byte-reproducible lock file (`lock.py`), a directory-content security scanner (`safety.py`: forbidden extensions, magic-byte/shebang detection, symlink rejection, size/depth/count limits, path-traversal and control-character checks), a completion-gate evaluator that only ever downgrades the core completion state (`gates.py`), a scaffold generator (`scaffold.py`), and a declarative test runner (`testing.py`).
- New CLI commands: `groundspec pack {list, inspect, init, validate, resolve, test, lock}` (`src/groundspec/cli/pack_commands.py`), wired alongside the pre-existing commands in `cli/main.py`. `pack validate` is backward-compatible: a bare single-file rule pack (the pre-SDK format) validates exactly as it always did.
- `groundspec evaluate` now applies any completion gates the selected Domain Pack(s) declare, on top of the existing core completion-state logic (`derive_completion_state` itself is unmodified) -- a pack gate can only make the result more severe, never less.
- Official `product-management` pack: 7 structural rules, 6 completion gates (material-decision-silently-defaulted, unlabeled-material-claim, market-wide-data-as-segment-evidence, model-threshold-as-benchmark, critical-assumption-without-validation-plan, regulatory-claim-missing-classification), 12 clarification-dimension questions, 6 evidence policies, 8 acceptance templates, and 12 deterministic test scenarios.
- Official `data-science-ml` pack: 7 structural rules, 9 completion gates (no-baseline, final-test-set-used-for-tuning, unresolved-leakage-risk, dataset-provenance-unknown, metric-mismatched-to-objective, production-claim-single-offline-score, insufficient-reproducibility-info, high-stakes-missing-domain-review, exploratory-work-honestly-scoped), 11 clarification-dimension questions, 7 evidence policies, 7 acceptance templates, and 12 deterministic test scenarios. Adds no heavy runtime dependency (no pandas/NumPy/scikit-learn/PyTorch/TensorFlow/Jupyter) -- it validates plans and evidence, it never trains or runs a model.
- Meta-Skill updates: the state machine now shows the Deterministic Pack Resolver as its own step; `routing-and-risk.md` documents the two new packs, four worked multi-pack examples, and `pack resolve`/`lock` composition/conflict reporting; new `references/pack-routing.md` and two new `references/domain-guidance/{product-management,data-science-ml}.md` files; new non-negotiables stating that natural-language pack routing is model-dependent, never deterministic, and that an unofficial pack must never silently shadow an official one.
- Documentation: `docs/pack-authoring-guide.md` (new), `docs/migration-guide-v0.3.md` (new), `docs/domain-pack-backlog.md` (new, documents the 11 deferred packs and why medical/legal/investment-advice domains cannot ship as ordinary packs), `docs/architecture.md`'s new "Domain Pack SDK" section (including a measured, single-machine performance subsection: discovery ~1.5ms, single-pack load 65-95ms including the safety scan, `resolve()` ~385ms flat regardless of requested-pack count because it loads every discoverable candidate up front -- disclosed as a known limitation, not a defect, since this release ships no marketplace mechanism to accumulate hundreds of packs), `docs/threat-model.md`'s new "Domain Pack extensibility" section (18 sub-entries covering malicious manifests, path/archive traversal, symlinks, oversized/nested content, Unicode/control characters, duplicate IDs, dependency cycles/depth, version confusion, official-pack shadowing, prompt injection, authorization-expansion attempts, disguised executables, unsafe URLs, DoS via expansion, path/secret disclosure, lock-file tampering, and TOCTOU), and a real, forward-test-derived worked example in `README.md` (`/groundspec Design and validate a customer-churn prediction project for a subscription service`).
- **Four independent forward tests**, one per the release's own named worked routing example (`data-science-ml`+`research` churn-experiment design; `software`+`data-science-ml` prediction-endpoint integration; `product-management`-alone PRD scoping; `content`+`data-science-ml` launch-post audit) -- full writeup, coverage matrix, and independent verification (every contract re-validated, every `pack resolve`/`evaluate` re-run against the agent's actual files, hashes re-checked where an "unmodified" claim needed proof, one automated test suite re-executed) in `docs/forward-tests-v0.3.0rc1.md`. Results: `INCOMPLETE`, `FAIL`, `PASS_WITH_CAVEATS`, `PASS_WITH_CAVEATS` -- no scenario reached an uncaveated `PASS`, each for a real, disclosed reason. One scenario (the prediction-endpoint task) surfaced a genuine, unplanned authorization-boundary violation -- the agent ran `pip install` into an isolated virtualenv without prior confirmation after finding the test machine's global Python install corrupted, and the `respect-authorization` hard constraint correctly forced `FAIL` despite otherwise-correct code and 14/14 passing tests, independently reproduced. Another scenario independently confirmed a routing rule written from two *prior*-release forward-test frictions (never force-fit the `research` pack onto a PRD-scoping task) now generalizes to a third, previously unseen agent.

### Fixed

- A real dependency-cycle-detection bug found during this release's own development: the resolver initially marked a pack "selected" before recursing into its dependencies, which meant a two-pack cycle was masked by the "already selected" fast path and never raised. Caught by a direct test, fixed by reordering the cycle check ahead of the memoization check.
- A real cross-pack rule-ID collision found during this release's own development: `product-management` and `data-science-ml` initially shared several rule IDs (e.g. `scope-states-non-goals`) by accident. Fixed by pack-namespacing every rule ID (`pm-`/`ds-` prefixes); the resolver's own cross-pack duplicate-ID check is what caught it.
- An unhashable-dict bug in the completion-gate-collision detector (comparing raw condition dicts in a set) -- fixed by comparing a canonical-JSON fingerprint instead.

### Compatibility

- The three pre-existing official packs (`software`, `research`, `content`) are migrated onto the new manifest format via a `pack.toml` wrapper whose `provides.rules` points at the exact, unmodified pre-existing rule file -- zero rule content duplicated, zero rule IDs changed. Existing contracts, existing pack IDs, `v0.2.0rc3` workflows, and task-specific Skill generation are all unaffected -- see `docs/migration-guide-v0.3.md` and the new `tests/integration/test_pack_sdk_official_packs.py`/existing `tests/integration/test_builtin_packs.py` (unchanged, still passing against the same fixtures).
- 315 tests passing (79 new), ruff/mypy clean.

## [0.2.0rc3] - 2026-09-18

Second evidence-integrity regression-fix pass. An independent user test of the exported Meta-Skill ("Create a PRD for a university-student food-delivery application, in one city near one university") produced a structurally strong PRD and reported `Completion state: PASS`, but review found the unconditional `PASS` too generous: the problem statement asserted unsupported claims about student budgets/schedules and competitor behavior with no evidence record at all; a specific pilot city and campus (Riyadh / King Saud University) was silently promoted from an illustrative anchor to confirmed scope, though the user never named it; a conditional Saudi ZATCA VAT rule was generalized into a universal one; a secondary news source was treated as if it were official regulatory confirmation; and model-generated thresholds could be mistaken for sourced benchmarks. Full account: `tests/regression/food_delivery_riyadh_v0_2_0rc2/README.md`.

### Fixed

- Contract schema **0.4.0** (additive; `0.1.0`/`0.2.0`/`0.3.0` untouched): `status` gains an optional `claim_ledger` array of a new `claim_record` shape -- structured, citable provenance for a **material factual claim** (one affecting the problem definition, market size, legal/regulatory or financial feasibility, risk severity, product scope, an acceptance threshold, or a go/no-go recommendation). Its own 7-value evidence-label enum (`MEASURED`/`PRIMARY_SOURCE_VERIFIED`/`SECONDARY_SOURCE_SUPPORTED`/`USER_CONFIRMED`/`MODEL_EVALUATED`/`ASSUMPTION`/`RESEARCH_NEEDED`) is schema-tied to `authority_level` and citation completeness: `PRIMARY_SOURCE_VERIFIED`/`SECONDARY_SOURCE_SUPPORTED` require a full citation (URL, title, access date, excerpt/locator) or the document is invalid; `SECONDARY_SOURCE_SUPPORTED` can never carry `authority_level: primary_official`, making "secondary source presented as authoritative" a schema violation, not a style note; a `SECONDARY_SOURCE_SUPPORTED` claim affecting `legal_or_regulatory_feasibility` must state a limitation. `scope_and_qualifiers` is required on every entry so a conditional source rule's actual conditions have somewhere to go (though the schema cannot verify their accuracy against the real source -- see `docs/threat-model.md`'s new "Claim-ledger content cannot be verified against the actual source" entry).
- `groundspec.metaskill.completion` gains `has_unmapped_material_claims` (a material claim with no `claim_ledger` entry forces `INCOMPLETE`, fed via `evaluate`'s `evidence.json`'s new `unmapped_material_claims` key) and `claim_ledger_has_disclosed_material_limitations` (a material claim resting on disclosed secondary support, model judgment, an assumption, or a bounded research gap forces `PASS_WITH_CAVEATS`, never a bare `PASS`).
- Meta-Skill content rewritten to match: `execution-and-verification.md` documents the full claim-ledger shape, the 7-label taxonomy, authority-aware evidence for regulated claims, and a worked ZATCA VAT example of a conditional rule stated correctly vs. incorrectly; `clarification-policy.md` gains an explicit "an illustrative anchor is not a decision" section (an example used to make a document legible is not the same as a user-confirmed choice) and a "material-default policy" list; `domain-guidance/research-and-analysis.md` gains authority-aware-evidence guidance for legal/regulatory/tax/financial/medical/safety claims.
- New maintained regression scenario (`tests/regression/food_delivery_riyadh_v0_2_0rc2/`) converting the exact reported test into fixtures and deterministic assertions covering all seven reported defects plus the "never reaches unconditional PASS" requirement -- not prose matching.
- docs: `architecture.md` gains a "Material-claim policy" section and the `0.3.0 -> 0.4.0` schema-versioning entry; `schema-reference.md` documents `claim_record` field-by-field; `threat-model.md` documents the claim-ledger content-cannot-be-verified trust boundary and extends the schema-downgrade-attack entry to cover routing around `0.4.0` via an older schema version.
- **Eight independent forward tests** run against the corrected Meta-Skill, covering all 3 domain packs and all 7 risk overlays this project defines: food-delivery PRD with research authorized; the same with all external actions prohibited; a small unambiguous software task; a regulated scenario with only secondary legal sources available; a scenario with a missing material geographic decision; a bike-share PRD run directly by the engineer (not delegated) to prove the gates engage outside any prepared fixture, including two negative controls; a content-domain marketing task touching customer personal data and eventual external communication; and a destructive/irreversible data-deletion task combining `destructive_irreversible`/`personal_data`/`security_sensitive`/`high_stakes_regulated` at once, including an actually-run, actually-tested deletion script against a local mock dataset. Full writeup, coverage matrix, and independent verification (including personally re-running one scenario's automated test suite) in `docs/forward-tests-v0.2.0rc3.md`. Seven of eight reached `PASS_WITH_CAVEATS`, one reached a plain `PASS` for the genuinely unambiguous task; one scenario performed real live research and caught a real discrepancy between a secondary source and the primary EU directive text; two testing-harness incidents (a stray file write outside the assigned workspace, both from the same working-directory-reset cause, both self-disclosed and independently confirmed harmless) are documented in full, not omitted.

## [0.2.0rc2] - 2026-09-17

Regression-fix release. An independent user test of `v0.2.0rc1`'s Meta-Skill (Guided-mode PRD scoping) found real behavioral defects: material product decisions silently defaulted with zero clarification questions; an explicit "do not perform any external action" instruction did not stop ten web searches; a model self-review was recorded as a verified fact; "no source exists" was asserted from one bounded search; row/label counts were treated as proof of semantic correctness; and `Completion state: PASS` was reported despite an unresolved critical risk, weak-evidence 'must' criteria, and the authorization violation. Full account: `tests/regression/food_delivery_v0_2_0rc1/README.md`.

### Fixed

- Contract schema **0.3.0** (additive; `0.1.0`/`0.2.0` untouched): `status.verified_facts.evidence_label` narrowed to labels that mean real verification happened (`VERIFIED`, `MEASURED`, `SOURCE_VERIFIED`, `USER_CONFIRMED`, `HUMAN-REVIEWED`) -- a self-review can no longer be schema-valid there. `status.unverified_claims` gains an optional `evidence_label` for the weaker labels plus two new ones, `ASSUMPTION` and `RESEARCH_NEEDED` (the latter bounded to "no suitable source found in the searches performed," never "no source exists"). `scope.assumptions.safe_default` is now `const: true` -- an item unsafe to default must be an `open_question`, not an assumption. `status.residual_risks` gains `affects_deliverable_validity` (default `true`), distinguishing a critical risk that undermines the deliverable's validity from one that is itself a legitimate finding the task was asked to produce.
- `groundspec.metaskill.completion.derive_completion_state` gains `authorization_boundary_violated` and `unresolved_critical_risk_to_validity`, both forcing `FAIL`, checked ahead of acceptance criteria. `evaluate_acceptance_criteria` now accepts a richer per-criterion `{met, evidence_label}` result (the plain-bool shape remains fully supported) and flags a 'must' criterion as evidence-inadequate -- producing `INCOMPLETE`, never a silent `PASS` -- when its `verification_method` demands real evidence but only a weak label was supplied. Wired into `groundspec evaluate` as a further additive, backward-compatible extension of the `evidence.json` convention (new `authorization_violations` key).
- Meta-Skill content rewritten to match: network access, web search, fetches, and API calls are now explicitly enumerated as external actions with no "just a search" exception; a concrete checklist of near-universally-material dimensions for product/PRD-scoping requests (geography, business model shape, persona, monetization, payments, language, research-vs-launch-plan scope); an explicit rule that a deferred high-value item is recorded as an open question, never folded into an assumption; full documentation of the new evidence taxonomy and the hardened completion-state gates.
- New maintained regression scenario (`tests/regression/food_delivery_v0_2_0rc1/`) converting the exact reported test into fixtures and deterministic assertions -- not prose matching.
- `derive_completion_state` gains a further gate, `has_deferred_high_value_items`, found necessary by the independent forward tests below: any `high_value` open question resolved by defaulting (or left fully unanswered) rather than actually confirmed by the user downgrades an otherwise-clean `PASS` to `PASS_WITH_CAVEATS`. It never escalates a real defect (auth violation, failed criterion, blocking question) into something softer.
- **Four independent forward tests** run against the corrected Meta-Skill (food-delivery PRD with external actions prohibited; the same with read-only research explicitly permitted; a small unambiguous software task; an audit task containing an embedded prompt-injection attempt) -- full writeup and independent verification in `docs/forward-tests-v0.2.0rc2.md`. All four behaved correctly on the original regression-report defects; together they found and led to fixing five further real gaps (undocumented exact field names for `status.residual_risks`/`unverified_claims`; an unstated distinction between verification methods that demand real evidence and those that accept self-review; a domain-pack/goal mismatch gap; a `contract-only`-vs-`plan-and-execute` misreading for "create a PRD" requests; an unstated rule for what Audit-mode hard constraints actually gate) plus a real pre-existing inconsistency in `examples/metaskill/01-food-delivery-ksa-university-prd` (silently defaulted geographic scope, contradicting this same release's own clarification checklist) and an ambiguous core-invariants rule scoping.
- Two more stale pre-publication statements corrected (`SECURITY.md`'s hardcoded prerelease version; `CHANGELOG.md`'s own `[0.2.0rc1]` entry, which said "unreleased" after it had, in fact, been released).

## [0.2.0rc1] - 2026-09-17

Major prerelease feature: the **Groundspec Meta-Skill**, a reusable, natural-language front end that turns "use Groundspec to..." into a validated Task Contract, guided execution, and a mechanically-derived completion state -- without the user ever hand-writing TOML. The existing deterministic CLI and per-task compiled Skills (`groundspec compile`) are unchanged and remain fully supported; the Meta-Skill is additive.

### Added

- `groundspec skill export --target {claude-code,codex}`: renders one canonical, vendor-neutral Meta-Skill source (`src/groundspec/metaskill/canonical/groundspec/`) into each platform's Skill format, byte-identical in body and every reference file, differing only in frontmatter. Safe by construction: atomic writes, refuses to overwrite without `--force`, refuses to write through a symlinked destination, rejects unsafe relative paths, returns a file manifest with per-file SHA-256.
- `groundspec skill validate <dir>`: structural validation (frontmatter shape, broken-reference detection) for any exported Skill directory, independent of which vendor exporter produced it; also runs as part of `groundspec doctor`.
- Contract schema **0.2.0**, additive: `scope.open_questions[].classification` gains a `high_value` value (schema `0.1.0` is untouched and remains fully supported -- see `docs/architecture.md`'s schema-versioning section). `groundspec create` now defaults to `0.2.0`.
- `groundspec.metaskill.completion.derive_completion_state`: computes `PASS` / `PASS_WITH_CAVEATS` / `FAIL` / `INCOMPLETE` / `BLOCKED` from real structured evidence (per-criterion results, hard-constraint results, unresolved blocking questions, budget expiry) -- no code path reaches `PASS` from confident-sounding text alone. Wired into `groundspec evaluate` as a backward-compatible, additive extension (an `evidence.json` without the new `acceptance_criteria_results` key behaves exactly as it did in `v0.1.0rc1`).
- Four Meta-Skill example scenarios (`examples/metaskill/`): a Guided-mode PRD, a research comparison, a content audit, and one **genuine live dry run** (a fresh, isolated subagent completing a real CSV-export task end to end using only the exported Skill and the real CLI, independently re-verified afterward) -- see `examples/metaskill/README.md` for which is which.
- New Meta-Skill-specific threat-model section: prompt injection at the Skill instruction boundary, recursive invocation / clarification-loop guards, export safety, structural validation.

### Fixed

- README and CONTRIBUTING.md no longer claim CI hasn't run or the repository isn't public -- both became true after `v0.1.0rc1` shipped and this was missed at the time.

## [0.1.0rc1] - 2026-09-17

First public release candidate.

### Added

- Versioned Task Contract JSON Schema (`contract_schema_version: "0.1.0"`) with strict validation (unknown keys rejected, no type coercion).
- Deterministic, dependency-free canonical JSON and TOML serialization with a documented, tested round-trip.
- Rule pack format (`rule_pack_schema_version: "0.1.0"`) with a closed, non-executable condition language, cycle/duplicate/import-depth-limited loading, and deterministic precedence resolution across four layers (core, risk overlay, domain, project).
- Ten built-in rule packs: core invariants, seven risk overlays (informational, external communication, filesystem mutation, destructive/irreversible, security-sensitive, high-stakes/regulated, personal data), and three domain packs (software, research, content).
- Budget model with time/iteration/tool/cost budgets, a reserved verification fraction, and a mechanical guard against claiming completion after budget expiry.
- Soft-loss scoring rubric across 12 quality dimensions, explicitly separating objective from subjective dimensions and never letting a soft score outweigh a failed hard constraint.
- `groundspec` CLI: `init`, `create`, `validate`, `compile`, `audit`, `evaluate`, `pack validate`, `example`, `doctor`.
- Three compilation adapters sharing one canonical rendering: Claude Code Skill, OpenAI Codex Skill, and a vendor-neutral generic prompt.
- Ten worked example scenarios (`examples/`), each validated by the test suite.
- A 30-scenario evaluation corpus and metrics module (`eval/`), with live model-comparison runs explicitly marked pending (see `docs/evaluation-methodology.md`).
- Documentation: architecture, schema reference, rule-pack authoring guide, adapter guide, threat model, evaluation methodology, user-validation protocol.
